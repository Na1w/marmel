Marmel new-UI preview - deterministic TestBackend frames of TuiRenderer::draw_new_ui
Captured on branch feature/new-ui by a temporary `preview_dump` test in src/ui/tui/tests.rs,
built from a seeded scenario (7-task plan with 3 checked; three live worker rows running /
queued / paused; tokens 12.4k in / 3.2k out; ctx 13.5k of 30k; project clock 10m 12s; draft
"add the focus badge to every pane title"). The scaffolding test is deleted again after this
file is written; the seeded scenario survives unchanged as `live_worker_scenario()` in
src/ui/tui/tests.rs, and the frame tests in that file pin the annotated rows cell by cell.
Frames are cell-by-cell symbol dumps (style/colour stripped), trailing blanks trimmed.

Same six cases as the t-009c audit recorded, regenerated after the t-009d fixes. The rows the
audit called out are annotated on the `>>` lines under the frame they belong to; the "was:"
text is the same cell of the same case in the t-009c capture.

The two `M4 Split` frames (cases b and c) have since been laid out again for the
one global pane-slot rule of `0f82198`: the Execution Plan owns the leading slot
(the wide left column, or the top row where the frame stacks) and the Transcript
the trailing one. Those two frames are hand-set for that rule rather than
re-captured; every row the `>>` annotations call out is unchanged.

>> Pane slots (t-024b, `0f82198`) — the Execution Plan owns the wide leading
   column and the Transcript the head of the trailing side column, over the
   Workers. The frame above is laid out for that rule: the transcript re-wraps
   into the narrower side column (its last 10 wrapped lines, scrollbar on the
   right edge), and the plan body fits the 58-cell wide column without
   scrolling, so the plan no longer carries a scrollbar there.
>> Defect 1 — Workers bottom tally. Was `└ ▶ running 1 ⏸ paused 1 ⧗ queued 1 ✓ d┘`: the tally
   was fitted to `rect.width` (40) while a border row is `width - 2` (38), so ratatui cut the
   last 2 cells silently — `✓ done N`, the `1/3` position and the detail chip were gone and
   nothing marked the cut. Now: `└ ▶ 1 ⏸ 1 ⧗ 1 ✓ 0  1/3  detail 0/0 ────┘` (fitted to
   `title_width`, and §7.2 drops the word labels before it drops a count).
>> Defect 3 — queued roster row. Was `⧗ queued researcher_specialist t-0…`: the `(2/3)` rank
   was a tail field and never survived a clipped row. Now `⧗ queued 2/3 researcher_specialist…`
   — the rank rides the state field, as in the §2.2 sample row `validator ⏸ (Queued 2/3)`.
>> Defect 2 — status row 1. Was ` Tokens 12.4k in / 3.2k out | 3a | ctx 45%`: 41 cells of a
   100-cell row, with ~58 free, because `fit_fields` deleted whole fields — `1p`, `1q`, the
   worker names and the clock. Now ` Tokens 12.4k in / 3.2k out | 3a | ctx 45% | 1p | 1q | coder_specialist-t-004… | elapsed 10m 12s`
   = 92 cells: counts kept, name list clipped with `…`, clock back on the row.
>> Defect 4 — status row 2. Was ` ● LIVE  plan:on  workers:on  think:off  3a 1p 1q`; the
   scroll-state chip now lives only on the transcript border row above.
